# 1. 双方头像上传与即时刷新

## 目标

管理面板可以分别上传、预览、替换 SOOYA 头像和用户头像；保存后聊天界面立即刷新，重启后仍生效。

## 必须实现

- 管理端提供“SOOYA 头像”和“用户头像”两个独立上传入口
- 支持常见图片格式，服务端验证真实 MIME、文件大小和内容
- 图片进入受管理的媒体存储，不写任意路径
- Persona 配置保存稳定的媒体 URL 或媒体引用
- 替换头像后，旧头像在不再被任何记录引用时可被安全清理
- 聊天顶部、空状态、消息列表头像同步刷新
- 上传失败显示明确原因，不能留下半写入文件或失效配置
- 页面刷新与服务重启后头像保持正确

## 验收

- [ ] 分别上传两张不同头像后，所有对应位置显示正确
- [ ] 替换头像后无需手动清缓存即可看到新头像
- [ ] 非图片、超限文件和损坏图片会被拒绝
- [ ] 重启后仍使用已保存头像
- [ ] 无未引用的旧头像无限堆积

# 2. 完整 Web Push 通知

## 目标

PWA 在后台或关闭后，也能在机器人回复完成时收到系统通知；点击通知能返回对应聊天。

## 必须实现

- 服务端生成或读取稳定的 VAPID 配置
- 提供 Push 公钥、订阅、取消订阅接口
- 订阅信息持久化，支持 endpoint 去重和失效清理
- Service Worker 处理 `push` 与 `notificationclick`
- 回复完成后触发推送，不在流式每个片段重复通知
- 当前页面可见且处于前台时避免重复系统通知
- 推送正文不泄露密钥、管理信息或过长敏感内容
- 处理 404/410 失效订阅并自动删除
- 管理面板或聊天设置中提供启用、关闭、重新授权状态

## 验收

- [ ] 安装 PWA 后可完成订阅
- [ ] 页面后台时收到一次回复通知
- [ ] PWA 完全关闭时仍可收到通知
- [ ] 点击通知打开或聚焦聊天页面
- [ ] 取消订阅后不再推送
- [ ] 失效订阅会被清理，不会持续报错

# 3. 图库安全删除与回收站

## 目标

图库删除默认进入回收站，不立即破坏聊天记录；支持恢复和永久清理。

## 必须实现

- 媒体增加软删除状态与删除时间
- 图库默认只显示正常图片，可切换回收站
- 删除操作进入回收站，不立即删除原文件
- 回收站支持单个/批量恢复
- 永久删除前检查消息、贴纸、头像等引用关系
- 被引用媒体不得无提示永久删除；必须阻止或给出明确影响
- 支持清空回收站与按保留天数自动清理
- 聊天引用已在回收站中的媒体时仍可显示，或提供明确占位策略

## 验收

- [ ] 删除图片后在正常图库消失、在回收站出现
- [ ] 恢复后原聊天和图库均正常
- [ ] 被引用媒体不会被静默永久删除
- [ ] 批量恢复与批量永久删除行为正确
- [ ] 自动清理只处理满足条件且可安全删除的媒体

# 4. 图库搜索、筛选、收藏与批量下载

## 目标

图库能够快速定位、整理和导出收到、上传或生成的图片。

## 必须实现

- 按来源筛选：收到、用户上传、机器人生成、其他
- 按时间范围筛选
- 按文件名、媒体 ID、关联文本或标签搜索
- 收藏/取消收藏并持久化
- 只看收藏
- 多选、全选当前结果、取消选择
- 批量下载，生成结构清晰的 ZIP 或浏览器兼容导出
- 显示图片数量、大小和筛选结果统计
- 筛选、收藏、选择状态在常规操作中不互相破坏

## 验收

- [ ] 搜索和筛选组合使用结果正确
- [ ] 收藏刷新后仍保留
- [ ] 批量下载内容与所选项目一致
- [ ] 大量图片下仍可分页或渐进加载
- [ ] 回收站项目不会混入普通导出，除非明确选择

# 5. 图片缩放、拖动与分享

## 目标

图片查看器在桌面与移动端都具备自然的查看和导出体验。

## 必须实现

- 单击图片打开带模糊背景的查看器
- 左右滑动切换
- 下滑或点击背景退出
- 双击放大/还原
- 双指捏合缩放
- 放大后单指拖动查看细节
- 缩放时禁用误触切图和下滑关闭
- 提供保存
- 支持 Web Share API 时提供分享；不支持时合理降级
- 键盘支持 Esc、左右方向键、放大缩小快捷操作
- 切图或关闭时正确复位缩放和拖动状态

## 验收

- [ ] iOS/Android 常用触控手势不冲突
- [ ] 桌面鼠标与键盘操作完整
- [ ] 放大图片可拖动且不会越界失控
- [ ] 保存与分享失败时有可理解的降级行为
- [ ] 浏览器返回键只关闭当前查看器，不破坏页面历史

# 6. 消息长按操作菜单

## 目标

对聊天消息进行常用操作，并在移动端与桌面端保持一致。

## 必须实现

- 移动端长按、桌面端右键或显式菜单按钮打开操作菜单
- 文本消息支持复制全文
- 支持复制指定消息内容中的文本部分
- 支持引用/回复到该消息
- 用户消息支持重新发送
- 失败消息支持重试
- 自己发送且尚可撤销的消息提供删除/撤回策略；不得静默破坏上下文
- 图片提供查看、保存、进入图库
- 音频提供播放、保存或复制转写文本
- 菜单具备焦点管理、键盘关闭和无障碍标签

## 验收

- [ ] 长按不会误触页面滚动或文本选择
- [ ] 复制、引用、重发、重试均作用于正确消息
- [ ] 操作失败有提示且不会产生重复消息
- [ ] 菜单在窗口边缘不会超出可视区域
- [ ] 键盘和屏幕阅读器可操作

# 7. 情绪语音控制面板与试听

## 目标

管理面板可配置机器人何时发语音、不同情绪如何表达，并能在保存前试听。

## 必须实现

- 展示 TTS 能力是否可用及失败原因
- 配置启用状态、发送频率、最大字符数、是否附带文字
- 配置默认音色、语速、音调、音量等供应商支持参数
- 至少支持中性、开心、难过、生气、温柔等情绪映射
- 不支持某参数的供应商应禁用对应控件或明确提示
- 试听输入框与试听按钮
- 试听生成临时音频，不污染正式聊天记录
- 保存后立即生效，重启后保持
- 配置中不得泄露 API Key

## 验收

- [ ] 各情绪可分别试听
- [ ] 配置保存、刷新和重启后保持
- [ ] 禁用 TTS 后机器人不生成语音
- [ ] 超长文本按策略截断或拆分，不导致请求失控
- [ ] 不可用模型显示明确错误，而不是按钮无反应

# 8. 世界引擎真正落地

## 目标

将现有世界引擎设计从文档变成可持久化、可注入上下文、可审计的运行时能力。

## 实施依据

必须结合：

- `docs/superpowers/specs/2026-07-29-sooya-world-engine-design.md`
- 当前单用户、单人格、单会话约束
- 现有消息、记忆、摘要、作业和事件总线架构

## 必须实现

- 世界状态持久化表与迁移
- 世界实体、关系、事实、场景或时间线的稳定数据模型
- 从对话中提取候选世界更新
- 更新必须经过结构校验、去重、冲突处理和可追踪来源
- ContextBuilder 在预算内注入相关世界状态
- 世界更新不得覆盖用户明确设定或高可信事实
- 管理端可查看、搜索、编辑、禁用、删除和重建世界数据
- 提供导出与导入
- 变更发布事件，相关页面能即时刷新
- 失败任务可重试，不阻塞正常回复
- 保持未来 CLI Agent 可扩展接口，但不引入多人格、多会话复杂度

## 验收

- [ ] 对话能产生可验证的世界状态更新
- [ ] 后续回复能正确使用相关世界状态
- [ ] 冲突事实不会被静默覆盖
- [ ] 删除或禁用后不再进入上下文
- [ ] 重启、备份和恢复后世界数据一致
- [ ] 世界引擎失败不影响基础聊天可用性

# 9. 存储限额、清理与孤立媒体治理

## 目标

在 1G 左右可用空间的服务器上长期稳定运行，避免媒体、临时文件和备份无限增长。

## 必须实现

- 管理面板显示总占用、分类占用、可用空间和趋势
- 配置媒体总限额、回收站保留时间、临时文件保留时间和备份保留策略
- 检测数据库有记录但文件不存在的媒体
- 检测文件存在但数据库无记录的孤立文件
- 检测已无任何消息、贴纸、头像或世界数据引用的媒体
- 提供预览式清理报告，先展示将删除内容和可释放空间
- 支持按类别安全清理：临时文件、过期回收站、孤立媒体、旧备份
- 达到软限额时告警，达到硬限额时阻止新的大文件写入但保持文本聊天
- 清理操作写入错误/审计记录，可追踪结果
- 定时维护任务具备互斥和失败恢复，避免与上传/备份竞争破坏文件

## 验收

- [ ] 管理面板统计与真实目录占用基本一致
- [ ] 孤立记录和孤立文件均能被识别
- [ ] 预览模式不删除任何内容
- [ ] 正式清理只删除报告内且满足安全条件的项目
- [ ] 空间不足时文本聊天仍可用
- [ ] 清理、备份、恢复并发时不会损坏数据库或媒体
