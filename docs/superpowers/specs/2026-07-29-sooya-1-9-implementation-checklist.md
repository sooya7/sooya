# 1. 双方头像上传与即时刷新

## 目标

管理面板可以分别上传、预览、替换 SOOYA 头像和用户头像；保存后聊天界面立即刷新，重启后仍生效。

## 必须实现

- 管理端提供“SOOYA 头像”和“用户头像”两个独立上传入口
- 支持常见图片格式，服务端验证真实 MIME、文件大小和内容
- 图片进入受管理的媒体存储，不写任意路径
- Persona 配置保存稳定的媒体 URL 或媒体引用
- 替换头像后，旧头像在不再被任何记录引用时可被安全清理
- 聊天顶部、空状态、消息列表头像同步刷新
- 上传失败显示明确原因，不能留下半写入文件或失效配置
- 页面刷新与服务重启后头像保持正确

## 验收

- [ ] 分别上传两张不同头像后，所有对应位置显示正确
- [ ] 替换头像后无需手动清缓存即可看到新头像
- [ ] 非图片、超限文件和损坏图片会被拒绝
- [ ] 重启后仍使用已保存头像
- [ ] 无未引用的旧头像无限堆积

# 2. 完整 Web Push 通知

## 目标

PWA 在后台或关闭后，也能在机器人回复完成时收到系统通知；点击通知能返回对应聊天。

## 必须实现

- 服务端生成或读取稳定的 VAPID 配置
- 提供 Push 公钥、订阅、取消订阅接口
- 订阅信息持久化，支持 endpoint 去重和失效清理
- Service Worker 处理 `push` 与 `notificationclick`
- 回复完成后触发推送，不在流式每个片段重复通知
- 当前页面可见且处于前台时避免重复系统通知
- 推送正文不泄露密钥、管理信息或过长敏感内容
- 处理 404/410 失效订阅并自动删除
- 管理面板或聊天设置中提供启用、关闭、重新授权状态

## 验收

- [ ] 安装 PWA 后可完成订阅
- [ ] 页面后台时收到一次回复通知
- [ ] PWA 完全关闭时仍可收到通知
- [ ] 点击通知打开或聚焦聊天页面
- [ ] 取消订阅后不再推送
- [ ] 失效订阅会被清理，不会持续报错

# 3. 图库安全删除与回收站

## 目标

图库删除默认进入回收站，不立即破坏聊天记录；支持恢复和永久清理。

## 必须实现

- 媒体增加软删除状态与删除时间
- 图库默认只显示正常图片，可切换回收站
- 删除操作进入回收站，不立即删除原文件
- 回收站支持单个/批量恢复
- 永久删除前检查消息、贴纸、头像等引用关系
- 被引用媒体不得无提示永久删除；必须阻止或给出明确影响
- 支持清空回收站与按保留天数自动清理
- 聊天引用已在回收站中的媒体时仍可显示，或提供明确占位策略

## 验收

- [ ] 删除图片后在正常图库消失、在回收站出现
- [ ] 恢复后原聊天和图库均正常
- [ ] 被引用媒体不会被静默永久删除
- [ ] 批量恢复与批量永久删除行为正确
- [ ] 自动清理只处理满足条件且可安全删除的媒体

- 试听生成临时音频，不污染正式聊天记录

## 目标

## 实施依据

必须结合：

- `docs/superpowers/specs/2026-07-29-sooya-world-engine-design.md`
- 当前单用户、单人格、单会话约束

## 必须实现

- 世界状态持久化表与迁移
- 世界实体、关系、事实、场景或时间线的稳定数据模型

- [ ] 冲突事实不会被静默覆盖

# 9. 存储限额、清理与孤立媒体治理

## 目标

在 1G 左右可用空间的服务器上长期稳定运行，避免媒体、临时文件和备份无限增长。

## 必须实现

- 管理面板显示总占用、分类占用、可用空间和趋势
- 配置媒体总限额、回收站保留时间、临时文件保留时间和备份保留策略
- 检测数据库有记录但文件不存在的媒体
- 检测文件存在但数据库无记录的孤立文件
- 检测已无任何消息、贴纸、头像或世界数据引用的媒体
- 提供预览式清理报告，先展示将删除内容和可释放空间
- 支持按类别安全清理：临时文件、过期回收站、孤立媒体、旧备份
- 达到软限额时告警，达到硬限额时阻止新的大文件写入但保持文本聊天
- 清理操作写入错误/审计记录，可追踪结果
- 定时维护任务具备互斥和失败恢复，避免与上传/备份竞争破坏文件

## 验收

- [ ] 管理面板统计与真实目录占用基本一致
- [ ] 孤立记录和孤立文件均能被识别
- [ ] 预览模式不删除任何内容
- [ ] 正式清理只删除报告内且满足安全条件的项目
- [ ] 空间不足时文本聊天仍可用
- [ ] 清理、备份、恢复并发时不会损坏数据库或媒体

# 六、最终收尾执行方案

本章用于后续执行者在不扩大范围、不重复开发、不提前宣布完成的前提下，完成 1–9 的最终闭环。执行顺序固定如下。

## 6.1 第一阶段：完成当前 Browser E2E

### 目标

取得一次未被取消、未超时、未跳过关键场景的桌面与移动 Playwright 完整结果。

### 执行步骤

1. 持续检查当前 `Browser end-to-end tests` Job。
2. 若 Job 仍在运行，不提交无关改动，避免新提交再次取消正在执行的工作流。
3. 若 Job 成功：检查 Playwright 报告，确认 Desktop 与 Mobile 项目均实际执行，且关键场景没有 `skip`、`fixme`、条件绕过或仅在单一项目运行；记录 Run ID、Job ID、测试数量和提交 SHA。
4. 若 Job 失败：获取日志、截图、trace、video 或 HTML report；按失败用例定位原因；只修复直接相关问题；补充对应回归断言；提交到测试分支后继续完整验证。
5. 若 Job 再次被取消：记录取消时间、Run ID、Job ID 和取消步骤；排查新提交、并发组、手动取消、超时或 Runner 异常；必要时调整 CI 的并发、超时和诊断上传策略，直到取得真实测试结论。

### 完成标准

- Desktop Playwright 全部通过
- Mobile Playwright 全部通过
- 无关键测试跳过
- 结果可追溯到明确的 Run ID、Job ID 和提交 SHA

## 6.2 第二阶段：逐项核对 1–9 自动化证据

这一阶段不按“文件存在”判断完成，而是逐条对照每个验收框。

### 1. 双方头像上传与即时刷新

需要确认：两个独立上传入口、真实 MIME/大小/损坏内容校验、受管理媒体存储、即时刷新、缓存失效、刷新和重启持久化、旧头像安全清理，以及失败时无半写入。自动化需要覆盖合法图片、伪造扩展名、错误 MIME、超限、损坏文件、双头像分别上传与替换、旧媒体引用保护。

### 2. 完整 Web Push 通知

需要确认：稳定 VAPID、公钥/订阅/取消接口、endpoint 去重、订阅持久化、前台抑制、回复完成后单次推送、正文裁剪、404/410 清理、取消后停止推送、点击通知打开或聚焦聊天。自动化覆盖订阅、去重、取消、失效清理及 Service Worker 的 `push`/`notificationclick`；真机覆盖后台和完全关闭状态。

### 3. 图库安全删除与回收站

需要确认：软删除、正常图库/回收站隔离、单个与批量恢复、聊天引用显示策略、永久删除引用检查、清空回收站和保留期任务安全性。测试需核对数据库记录与磁盘文件一致。

### 4. 图库搜索、筛选、收藏与批量下载

需要确认：来源、时间、文件名、媒体 ID、关联文本、标签组合查询；收藏持久化；多选和全选当前结果；批量导出与选择一致；回收站不混入普通导出；分页和统计正确。

### 5. 图片缩放、拖动与分享

需要确认：模糊背景、左右切换、下滑关闭、双击缩放、双指捏合、拖动、缩放期间防误触、状态复位、键盘、保存、分享降级和返回键历史。Desktop E2E 覆盖键鼠与历史，Mobile E2E 和真机覆盖触摸手势冲突。

### 6. 消息长按操作菜单

需要确认：移动长按、桌面右键/按钮、复制、引用、重发、重试、撤回占位、图片/音频操作、边缘定位、焦点管理、Esc、ARIA 和屏幕阅读器。测试需确保操作作用于正确消息且不产生重复。

### 7. 情绪语音控制面板与试听

需要确认：能力状态、启用/频率/字符数/附带文字、音色/语速/音调/音量能力控制、中性/开心/难过/生气/温柔映射、临时试听、不污染聊天、保存即时生效、重启持久化、禁用后不生成、超长策略、错误提示和 API Key 不泄露。

### 8. 世界引擎真正落地

需要确认：干净迁移与失败回滚、稳定数据模型、候选提取、结构校验、去重、来源、冲突处理、权威优先级、预算内上下文注入、禁用/删除过滤、管理、导入导出、事件刷新、失败重试、备份恢复一致性和基础聊天不受影响。
