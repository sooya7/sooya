# SOOYA PR #1 核验与修复设计

## 目标

以 `2026-07-29-sooya-1-9-implementation-checklist.md` 作为唯一功能范围，核验合并审查报告的 M-001 至 M-024，并修复已确认、且属于该范围的缺陷。所有改动仅提交至 `test/comprehensive-ci-20260729`；PR #1 在完成定义满足前保持 Draft，绝不修改或合并 `main`。

## 范围判定

审查报告是待核验候选集，不是事实或需求来源。每一项必须记录代码、测试、CI 或真机证据，并归入：确定存在、高可信存在、已修复、报告误判、测试不足、真机待验证或无法确认。

世界引擎仅核验实施清单要求的事实库、来源、冲突、上下文注入和管理能力。`2026-07-29-sooya-world-engine-design.md` 明确将模拟世界运行时（调度、离线补算、每日计划、主动消息）排除在本轮实现之外；仅因缺少这些能力而提出的 M-003 不实施，记录为范围误判。

## 实施批次

1. **基线与 CI**：独立检出 Head，执行安装、typecheck、build 和服务端测试；比较 PR Head 与 merge ref；读取已取消 E2E 的日志，定位取消或卡死的实际原因。
2. **数据安全**：以测试先行修复清理报告绑定、文件/数据库删除一致性、媒体精确引用、预览/实际统计一致性及媒体鉴权令牌泄露。
3. **世界事实库**：在不扩展模拟运行时的前提下，修复 token 预算、LIKE 转义、确定性归一化和批量导入事务问题；先建立设计范围矩阵。
4. **语音、Push 与 Service Worker**：统一试听与正式 TTS 参数解析；临时 Push 失败不删除有效订阅；修复缓存版本键与可见性同步的可验证缺陷。
5. **图库与交互**：只对真实代码路径确认的问题修复 Pointer 生命周期、history、长按和 ZIP；触控/PWA/iOS/Android 结论保留真机证据要求。
6. **最终验收**：执行完整本地验证、更新实施清单中的证据与未完成真机阻塞项，并检查 GitHub Actions 的完整成功运行。

## 每项修复方法

对每个确认缺陷先新增最小回归测试并观察其按预期失败；随后实施最小修复，运行该测试和关联测试组。不得使用 skip、only、静默 catch、`|| true` 或降低断言掩盖失败。每个批次完成后提交一次原子提交，并在实施清单中写明证据。

## 验证与边界

自动化验证不能替代 iOS/Android 真机的系统级通知、已关闭 PWA、触控手势和语音试听。无法在当前环境完成的真机项目将明确保留为阻塞项，不宣称成功。任何已取消、跳过、排队或进行中的 Actions job 都不计为 success。
