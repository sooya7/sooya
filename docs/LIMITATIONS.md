# SOOYA 已知限制

本文件只记录当前仍然成立的边界。验证状态以代码、测试、已合并 PR、CI 和明确的真实环境证据为准；没有证据时不得写成“已验证”。

---

## 1. 外部能力验证状态

SOOYA 的请求构造、流解析、媒体落盘、失败降级和重试路径都有自动化测试。部分能力已经在生产或真实网关链路中使用，但不同供应商协议仍需分别验收。

| 能力 | 当前已验证 | 仍需验证或注意 |
| --- | --- | --- |
| OpenAI Chat Completions / OpenAI 兼容接口 | 真实生产对话链路、SSE 解析、超时与重试 | 不同兼容服务的错误格式、限流策略和能力声明可能不同 |
| OpenAI Responses | 适配器、`output_text` 与增量事件解析测试 | 仍缺稳定的真实供应商端到端验收 |
| Anthropic Messages | 请求头、消息结构与增量解析测试 | 仍缺稳定的真实供应商端到端验收 |
| 图片生成 | 真实网关链路曾返回并落盘图片；`b64_json` 与 URL 两条代码路径有测试 | 上游账号池、额度、模型尺寸和返回格式仍可能不同 |
| Embedding | 维度校验、存储、召回和降级有测试 | 真实向量的长期召回质量需要实际数据评估 |
| STT | 上传、转写调用与失败处理有测试 | 火山 ASR 是独立的 WebSocket 二进制协议，尚未接入；准确率依赖供应商和音频格式 |

`/api/capabilities` 的 `configured` 或 `ok` 不能替代真实业务请求。静态配置可能错误声明模型支持图片、JSON mode 或其他能力。

---

## 2. 部署与运行边界

- Linux 原生部署已经在真实 systemd 环境运行；安装、升级、符号链接切换、健康检查和自动部署链路有实际使用记录。
- `upgrade.sh` 会在切换 `current` 前，以服务用户身份打开、写入并检查 SQLite 探针库；原生模块不可用时不会切换新 release。
- Nginx/TLS 的行为取决于实际部署配置；SSE 缓冲、上传大小、CSP、访问日志和来源限制需要运维侧保持一致。
- Dockerfile 与 compose 存在，综合 CI 会构建镜像并启动容器做验收；生产部署当前仍以 Linux 原生方式为主。
- 目标是单用户、低并发部署。数周以上的内存、磁盘、WAL 和媒体增长仍需持续观察。
- 新增大型原生依赖前，需要评估安装峰值内存、release 大小和回滚路径。

---

## 3. 功能边界（有意为之）

- 单人格，保存在 `config/persona.json`，没有人格切换。
- 单会话，固定使用 `conversation_id = "main"`，没有新建、删除或切换会话。
- 无注册、多账号、团队或工作区。
- `packages/server/src/agent/` 仍是架构预留，聊天主流程没有启用通用 Agent 执行器。
- Agent Shift 已废弃；仓库不再保留 Browser Use queue、定时唤醒或自动续班 workflow，`agent/handoff` 仅用于人工交接。
- 管理控制台已实现，管理 API 仍要求 `x-admin-token`。
- 生活引擎主动开口受部署层开关控制，面板设置不能绕过部署层关闭状态。

## 4. 已知技术限制

### 4.1 数据库与备份

- `better-sqlite3` 当前锁定在已验证的 12.x 范围；升级大版本前必须在目标架构验证原生模块。
- 只有 SQLite 明确报告损坏时才进入恢复流程。模块缺失、权限错误、磁盘满、锁冲突等“无法打开”会拒绝启动并保留原文件。
- 真正损坏且没有可验证备份时会 fail closed，不会建立空库继续服务。
- 外键不一致会被报告，但不会自动替换数据库。
- 媒体目录与数据库备份之间不是完全原子快照，极端情况下恢复后可能出现单个媒体 404。
- SQLite/WAL 的进一步打捞顺序和自动化恢复仍可加强。

### 4.2 记忆与世界检索

- Embedding 相似度是全表扫描，没有向量索引；记录达到万级后会逐渐变慢。
- Embedding 不可用时会退回全文或 bigram 检索，召回质量较低。
- 中文 FTS 使用 trigram；很短的查询词可能无法命中 FTS。
- 世界和记忆抽取依赖结构化模型输出；JSON mode 不兼容时的降级和可观测性仍需加强。
- 世界重建避免删除管理员导入且无法从消息恢复的条目的保护仍是待办。

### 4.3 模型能力

- `supportsVision` 等静态字段可能与真实模型能力不一致。
- `vision`、`summary` 未单独配置时可能回退到聊天模型，图片输入和 JSON mode 需要分别验证。
- 能力不匹配、网络超时和上游 5xx 的错误提示仍可能过于相似。
- 图片输入不被支持时，当前仍需补“丢弃图片后纯文本重试”的明确降级。

### 4.4 多媒体

- 多媒体通过内联标记编排，不依赖 tool calling；代价是模型必须遵守提示词。
- 单张图片超过限制时会退化为文本占位。
- 图片尺寸解析覆盖 PNG/JPEG/GIF/WebP；其他格式可能没有宽高元数据。
- 音频时长解析不依赖 ffmpeg；未知容器返回 `null`，不会编造时长。
- 图库主要展示原图，服务端缩略图尚未实现，大图较多时网络和内存开销明显。
- 媒体和头像已使用 ETag、304、私有 HTTP 缓存及客户端进程内缓存；长期缓存上限仍需观察。
- 删除被历史消息引用的表情或媒体需要统一引用保护，部分删除路径仍需复核。

### 4.5 并发与规模

- 设计前提是单用户；消息回复串行执行，多端同时发送会排队。
- SQLite 是单写者，大批量维护、备份和媒体整理会提高 IO。
- SSE 事件日志有保留上限；离线太久时会改用 REST 对账，消息不会丢，但中间增量事件可能丢失。
- SSE 重连路径仍需防止重复连接和孤儿读取循环。

### 4.6 前端与移动端

- 麦克风依赖 `MediaRecorder` 和安全上下文，需要 HTTPS 或 localhost。
- 浏览器决定录音容器；转写服务必须支持对应格式。
- iOS Web Push 需要安装到主屏幕并获得权限；真机端到端验收仍需用户完成。
- 未实现虚拟滚动，加载很多历史页后 DOM 数量会线性增长。
- 未实现完整 i18n，当前界面以中文为主。
- 目前只有浅色主题。

### 4.7 安全

- 单用户令牌是共享密钥，没有刷新令牌或吊销列表；泄露后需要更换并重启。
- 令牌保存在浏览器 `localStorage`。
- 受保护媒体由前端 `fetch` 通过请求头鉴权，再转为 Blob URL；凭据不应放在媒体 URL 查询参数中。
- 私有媒体响应使用 `Cache-Control: private`，可进入用户浏览器缓存，但不应由共享缓存或 CDN 保存。
- 没有独立 CSRF token，也没有应用级速率限制；公网部署应在反向代理层限制来源并限流。
- 上传文件只做类型、内容嗅探和大小限制，不做病毒扫描。

---

## 5. 明确不做的事

- 不引入 Kubernetes、微服务、Redis、Elasticsearch 或额外消息队列。
- 不内置第三方品牌美术素材。
- 不内置 QQ 登录、协议或数据。
- 不把真实 API Key、Token、Session ID、服务器登录方式或 Tunnel 配置写进公开仓库。

---

## 6. 建议的后续工作

1. 修复静态能力声明与真实端点不一致：图片输入失败时纯文本重试，JSON mode 不兼容时明确降级。
2. 为世界重建、表情删除和媒体永久删除补不可逆数据保护测试。
3. 实现服务端缩略图；依赖选择需先由用户决定。
4. 完成 Responses、Anthropic 和真实 STT 的端到端验收。
5. 增加 SSE 重连、图库并发加载和媒体删除的回归测试。
6. 历史消息增长后增加虚拟滚动。
7. 加强数据库与媒体的一致性快照及 WAL 打捞流程。
